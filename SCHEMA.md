# Registry schema

This document defines the public contract for snapshots stored under `registry/`.

> **Most snapshots are generated automatically** when a [documentation request](https://github.com/reclear-io/llmref/issues/new?template=request-docs.yml) is approved - you do not hand-write them. This document is the contract those artifacts follow, useful if you are submitting or reviewing a snapshot PR.

## Directory layout

```
registry/
  <technology-id>/
    <version>/
      llms.txt          # always present
      llms-full.txt     # only when the upstream license permits redistribution
      meta.json         # always present
opt-out.txt             # optional, repo root: snapshots withdrawn on request
```

`llms-full.txt` is **conditional**: it ships only when the snapshot's license
allows redistributing full text (see [License](#license)). Reserved-license
snapshots contain just `llms.txt` and `meta.json`; their full text is indexed for
search from a private store and never published here.

### Naming rules

| Segment | Rules |
|---|---|
| **technology-id** | Lowercase slug: letters, numbers, hyphens. No spaces or underscores. Example: `svelte`, `nextjs` |
| **version** | Exact upstream version string. Example: `5.0.0`, `14.2.0` |

## Artifacts

### `llms.txt`

Compact routing and summary file for models. Typically lists documentation sections with titles and canonical URLs.

### `llms-full.txt`

Full merged documentation artifact. Complete text content for the indexed version.
Present **only** when the upstream license permits redistribution
(`meta.json` → `license.redistribution_allowed` is `true`). Omitted for
reserved-license snapshots.

### `meta.json`

Snapshot metadata. Required fields:

| Field | Type | Description |
|---|---|---|
| `project` | string | Technology ID. Must match the directory slug. |
| `project_version` | string | Version string. Must match the version directory. |
| `snapshot_id` | string | Unique identifier for this snapshot (UUID recommended). |
| `snapshot_at` | string | ISO 8601 timestamp when this snapshot was generated. |
| `source_last_seen_at` | string | ISO 8601 timestamp when the upstream docs were last observed. |
| `content_fingerprint` | string | SHA-256 hex digest of the normalized docset content. Used for change detection. |
| `page_count` | integer | Number of pages or linked entries in the snapshot. |
| `source_root` | string | Official documentation root URL. |
| `embedding_model` | string | Embedding model used for semantic indexes, if any. |
| `chunking_profile` | string | Chunking strategy identifier. |
| `generator_version` | string | Version of the tooling that produced this snapshot. |
| `license` | object | Redistribution policy for the docs. See [License](#license). Present on snapshots generated by the current pipeline; absent on legacy snapshots. |

#### Example

```json
{
  "project": "svelte",
  "project_version": "5.0.0",
  "snapshot_id": "1bf98f06-6cee-4d83-ae88-4730a4855168",
  "snapshot_at": "2026-06-09T22:39:18Z",
  "source_last_seen_at": "2026-06-09T22:39:18Z",
  "content_fingerprint": "6a1e6dc6c06a8c504a0a4b7c2dff4088876270238a7e22b153a8dbcde838cb8c",
  "page_count": 7,
  "source_root": "https://svelte.dev",
  "embedding_model": "voyage-3-lite",
  "chunking_profile": "docs-v1",
  "generator_version": "0.1.0",
  "license": {
    "spdx": "MIT",
    "redistribution_allowed": true,
    "share_alike": false,
    "source": "repo-license"
  }
}
```

### `license`

Redistribution policy for the snapshot's upstream docs, detected by the pipeline.
It decides whether `llms-full.txt` (and the off-repo dumps) may be published.

| Field | Type | Description |
|---|---|---|
| `spdx` | string | SPDX id, or `unknown`. |
| `redistribution_allowed` | boolean | Whether full text may be published. `false` → `llms-full.txt` is omitted. |
| `share_alike` | boolean | License carries share-alike / attribution duties. |
| `source` | string | How it was determined: `override`, `declared`, `repo-license`, or `default`. |
| `reference` | string | Optional: URL the license was read from. |
| `notice` | string | Optional: short attribution / license notice. |

CI enforces the gate: a `redistribution_allowed: true` snapshot **must** include
`llms-full.txt` (with a matching `content_fingerprint`); a `false` snapshot **must
not**. Because llmref is non-commercial, NonCommercial (NC) Creative Commons terms
are treated as redistributable; NoDerivatives (ND) and unrecognized licenses are
not.

### Takedowns (`opt-out.txt`)

A newline-delimited list at the repo root of snapshots withdrawn on request. Each
line is a bare `<technology-id>` (whole project) or `<technology-id>/<version>`;
`#` comments and blanks are ignored. The serving API returns HTTP 451 for listed
entries and omits them from search.

#### Metadata maintenance

Include `meta.json` with as many fields as you can, but don't worry if something is incomplete or slightly off on your first pass. Maintainers routinely review and correct metadata before merge — timestamps, fingerprints, `page_count`, and other technical fields — because they know what each value should be and where it belongs. Focus on getting the artifacts and core identifiers right (`project`, `project_version`, `source_root`).

CI validates every `meta.json` field, fingerprint consistency, `page_count`, `llms.txt` links, and `registry/index.json` sync. Any failures must be fixed in the same PR before merge. If you are unsure about a value, run `python3 scripts/verify_registry.py` locally before opening the PR.

## Catalog index

`registry/index.json` is a machine-readable catalog of all indexed projects and versions. It is updated when snapshots are added or refreshed.

## Change detection

Snapshots are maintained by content fingerprint, not by schedule:

1. Each normalized page produces a page-level fingerprint.
2. Page fingerprints combine into a whole-docset `content_fingerprint`.
3. On refresh, a changed fingerprint triggers an update; an unchanged fingerprint means the docset is current.

## Historical compatibility aliases

A reviewed identity migration can retain old project/version routes as
compatibility aliases. Metadata and index entries both carry
`canonical_target: {"project": "qualified-id", "version": "exact-version"}`.
The target must exist as a leaf record with the exact same source URL and
original SHA-256. Missing targets, chains, cycles and changed originals fail
validation. An alias-only namespace has exactly one `legacy_default: true`,
freezing its previously served bare-name default. New ordinary captures use
the qualified IDs.

Changing a canonical target or frozen default requires the existing explicit
`source-move-approved` maintainer review. Policy-only maintenance of an unchanged
compatibility record retains its routes. This does not merge unrelated release
sequences or infer ownership from capture dates.

When an exact original is unavailable in the checked retained sources, metadata
may carry `archive_status: "unavailable"` with an explicit `archive_reason`.
Its fingerprint and routing remain retained. Serving and reconciliation expose
that state explicitly rather than substituting different bytes.

Captures from the wrong documentation scope use `capture_status: misqualified`
and a nonempty `capture_reason`; an optional `replacement_project` names a
valid project ID. This is distinct from an unavailable original. HTTP/MCP
resolution retains these annotations while full text and search fail closed.
The index repeats `capture_status` and `archive_status` when present.
Catalog annotations do not alter immutable revision identities.

Declared retired captures withhold public `llms-full.txt` regardless of the retained license permission. Their metadata, fingerprint and routing remain, without inventing an immutable pin when none existed. Public text removal requires separately verified private preservation; the declaration itself is not proof of preservation.
